# K-Apply

**한 번 입력한 이력 정보로 국내 채용 지원서를 자동으로 채워 주는 크롬 확장프로그램**

## 왜 만들었나요?

채용 사이트마다 이름·연락처·학력·경력·자격증을 매번 다시 입력해야 합니다. 항목은 거의 같은데 화면 구성과 입력 방식(검색형 학교명, 달력, 드롭다운, "입력사항 저장" 버튼 …)이 제각각이라 복사·붙여넣기도 번거롭습니다.

K-Apply는 이력 정보를 **브라우저에 한 번만 저장**해 두고, 지원서 화면에서 **버튼 한 번**으로 각 솔루션의 입력 방식에 맞춰 채워 줍니다. 제출은 항상 직접 확인한 뒤 사용자가 합니다.

## 주요 기능

- **채용 솔루션 자동 감지** — 페이지를 열면 그리팅·나인하이어·마이다스인 여부를 판별해 툴바 배지(`G` `9` `M`)로 알려 줍니다. `musinsacareers.com`처럼 기업 전용 도메인으로 운영되는 채용 사이트도 페이지 구조와 리소스 출처로 감지합니다.
- **기본 정보부터 이력 사항까지** — 기본 정보, 링크, 지원 경로, 병역·보훈·장애, 학력, 경력, 프로젝트, 대외활동·봉사, 교육 이수, 어학, 자격증, 수상.
- **반복 항목 자동 추가** — 학력·경력처럼 여러 건을 입력하는 섹션은 "항목 추가"·"입력사항 저장"·"+" 버튼을 눌러 저장된 건수만큼 채웁니다.
- **검증된 파일 첨부** — 이력서·포트폴리오·경력기술서를 첨부하고, 채용 사이트 서버가 **원본과 SHA-256이 같은 파일을 실제로 받았는지** 확인한 경우에만 성공으로 표시합니다.
- **학교 코드 선택** — 학교·전공·자격증은 각 솔루션의 코드 목록에서 정확히 같은 항목(캠퍼스 포함)을 고르고, 애매하면 추측하지 않고 알려 줍니다.
- **기존 입력 보존** — 이미 값이 있는 칸은 건너뜁니다(설정에서 덮어쓰기 가능).
- **결과 리포트** — 채운 항목, 건너뛴 항목, 직접 확인이 필요한 항목을 페이지와 팝업에 보여 줍니다.
- **세 가지 실행 방법** — 지원서 화면의 `K-Apply로 채우기` 버튼, 툴바 팝업, 단축키 <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd>.

| 주소 (각 사이트의 주소 검색 경유) | ✅ | ✅ | ✅ |

| 포트폴리오 · GitHub · 블로그 링크 | ✅ | ✅ | ✅ |
| 병역 · 보훈 · 장애 여부 | ✅ | ✅ | ✅ |
| 학력 (고등학교 · 대학교 · 대학원) | ✅ | ✅ | ✅ |
| 경력 | ✅ | ✅ | ✅ |
| 프로젝트 | ✅ | – | ✅ |
| 대외활동 · 봉사활동 · 교육 이수 | ✅ | – | ✅ |
| 어학 · 자격증 · 수상 | ✅ | ✅ | ✅ |
| 이력서 · 포트폴리오 · 경력기술서 파일 | ✅ | ✅ | 안내² |

✅ 자동 입력 · – 아직 지원하지 않음(또는 해당 솔루션에 없는 항목) · ² 자동 첨부하지 않고, 등록된 파일을 직접 첨부하라고 안내합니다.

> **마이다스인 새 지원서 화면** (`/v1/applicant/resume-form`, 예: 교보증권)은 화면 구조가 기존과 완전히 달라 별도 어댑터로 처리합니다. **기본정보**(이름·연락처·생년월일·성별·병역·장애/보훈 여부·주소·URL·국적), **학력 및 연구/경력**(고등학교·대학교·대학원·전공, 직장경력), **어학/자격/기타**(공인외국어시험·자격증·수상경력·학내외활동) 단계를 지원합니다.

각 기업이 지원서에서 켠 항목만 화면에 나타나므로, 실제로 채워지는 항목은 공고마다 다릅니다.

### 학교·전공 등 코드 목록 항목

세 솔루션 모두 학교·전공·자격증을 **코드가 붙은 목록**에서 고르는 방식입니다. 목록에서 고르지 않고 직접 입력하면 기업 쪽에서 학교 코드가 연결되지 않을 수 있어, K-Apply는 다음 규칙을 따릅니다.

| 상황 | 동작 |
| --- | --- |
| 목록에 같은 이름이 있음 (예: `서울고등학교`) | 그 코드 항목을 선택 |
| 캠퍼스별로 나뉨 (예: `서울대학교 (관악)`, `(연건)`) + 프로필에 캠퍼스 입력 | 해당 캠퍼스 항목을 선택 |
| 캠퍼스별로 나뉨 + 캠퍼스 미입력 | **추측하지 않고** "실패"로 알림 — 프로필에 캠퍼스를 입력하거나 직접 선택 |
| 목록에 없음 | "직접 입력하기"로 입력하고 **"확인 필요"** 로 표시 |
| 비슷한 이름만 있음 (예: `남서울대학교`) | 고르지 않음 |

**저장 예시** — 학교명에는 캠퍼스를 붙이지 말고 공식 명칭만, 캠퍼스는 따로 입력합니다.

| 학교 | 학교명 | 캠퍼스 | 본교/분교 | 결과 |
| --- | --- | --- | --- | --- |
| 한국외국어대학교 글로벌캠퍼스 (이원화) | `한국외국어대학교` | `글로벌` | 본교 | 그리팅 `한국외국어대학교` · 나인하이어 `한국외국어대학교 (글로벌)` · 마이다스인 본교 |
| 서울대학교 관악캠퍼스 | `서울대학교` | `관악` | 본교 | 나인하이어 `서울대학교 (관악)` |
| 캠퍼스가 하나인 학교 | `서울고등학교` | (비움) | (비움) | 정확히 같은 항목 |

캠퍼스 구분이 없는 목록(그리팅 등)에서는 캠퍼스를 입력해도 학교 항목을 그대로 고릅니다. **본교/분교**는 이를 따로 묻는 지원서(마이다스인)에서만 쓰며, 이원화 캠퍼스는 본교로 선택하면 됩니다.

### 주소

주소 칸은 세 솔루션 모두 **주소 검색 창에서 고른 결과만** 받습니다. 값을 억지로 써 넣지 않고, 각 사이트의 검색을 실제로 거칩니다.

| 솔루션 | 사이트의 주소 검색 | K-Apply의 동작 |
| --- | --- | --- |
| 그리팅 | Google 장소 검색 모달 | 도로명 주소로 검색 → **우편번호와 도로명 주소가 모두 같은 결과**만 선택 |
| 나인하이어 | 카카오(Daum) 우편번호 위젯 | 위젯이 사용자 선택 시 돌려주는 값(우편번호·도로명·지번)을 그대로 전달 |
| 마이다스인 | 도로명주소 검색(postcodify) | 도로명 주소로 검색 → **우편번호와 도로명 주소가 모두 같은 결과**만 선택 |
| 마이다스인 새 화면 | [주소입력] 도로명주소 검색 창 | 도로명 주소로 검색 → 도로명(+지번) 주소가 같은 결과가 **하나일 때만** 선택 → 입력된 우편번호·주소를 프로필과 대조 |

그래서 프로필의 주소는 **공식 표기**여야 합니다. 옵션 화면의 **[주소 검색]** 으로 입력하면 우편번호·도로명·지번 주소가 공식 표기로 채워집니다. 검색어는 사용자가 검색할 때만 주소 검색 서비스(postcodify, `api.poesis.kr`)로 전송됩니다.

### 첨부 파일 검증

"첨부된 것처럼 보이지만 실제로는 빈 파일이 제출되는" 일을 막기 위해 다음을 모두 통과해야 "입력"으로 표시합니다.

1. **저장 시** 파일 크기와 SHA-256을 기록하고, 저장 직후 다시 읽어 검증합니다. 빈 파일은 등록할 수 없습니다.
2. **첨부 직전** 저장된 파일을 다시 읽어 크기·SHA-256이 등록 당시와 같은지 확인합니다. 다르거나 내용이 없으면 첨부하지 않고 "실패"로 알립니다.
3. 업로드 칸이 요구하는 형식(예: "PDF 형식으로 제출해주세요", `accept` 속성)과 다르면 첨부하지 않습니다.
4. 첨부 후 페이지가 보내는 **실제 업로드 요청 본문의 SHA-256이 원본과 같고 서버 응답이 2xx**인지 확인합니다.
5. 화면에 첨부 완료 상태가 표시됐는지 확인합니다. 사이트가 거부하면 즉시 "실패"로 알립니다.

이미 첨부된 파일이 있으면 삭제에 확인 창이 필요한 파괴적 동작이므로 **덮어쓰기 설정과 관계없이 그대로 둡니다.**

### 결과 표시

| 상태 | 뜻 |
| --- | --- |
| 입력 | 값을 넣고 반영까지 확인함 |
| 확인 필요 | 입력했지만 사용자가 검토해야 함 (목록에 없어 직접 입력, 사용자가 채워야 하는 상세 칸 등) |
| 실패 | 넣지 못했거나 검증을 통과하지 못함 — 사유를 함께 표시 |
| 건너뜀 | 이미 값이 있어 그대로 둠 |

### 알려진 제한

- **마이다스인 2·3단계**(학력/경력, 어학/자격)는 솔루션의 화면 템플릿을 분석해 구현했으며, 실제 지원서에서의 검증 사례가 적습니다. 입력되지 않는 항목이 있으면 [제보](https://github.com/leestana01/K-Apply/issues/new/choose)해 주세요.
- **마이다스인 첨부 파일**은 형식 오류 시 페이지를 멈추는 경고창을 쓰는 구조라 자동 첨부하지 않고 직접 첨부를 안내합니다.
- **나인하이어**의 어학·자격증/수상·병역 하위 입력 폼은 기업 설정에 따라 구성이 달라, 일부 세부 항목이 "확인 필요"로 남을 수 있습니다.
- 나인하이어 보훈·장애 항목은 해당 항목이 있는 공개 공고가 모두 로그인을 요구해 실제 검증 사례가 없습니다.
- 선택지는 기업마다 다릅니다(예: 활동 구분에 "대외활동"이 없는 공고). 프로필 값과 맞는 선택지가 없으면 비슷한 값으로 대체하지 않고, 실제 선택지 목록과 함께 알려 줍니다.
- 마이다스인의 부전공·복수전공은 아직 지원하지 않습니다.
- **마이다스인 새 화면**의 학력·경력·수상·활동은 [+ 고등학교] 같은 버튼으로 항목을 추가해 채우며, 학교·전공·회사명은 목록에서 이름이 정확히 같은 항목만 고르고 없으면 직접 등록합니다(학교·전공은 "확인 필요"로 표시). "대표 1건만"처럼 개수 제한이 있으면 프로필의 첫 항목부터 넣고 나머지는 알려 줍니다.
- **YBM 성적 연동 기업**(예: 교보증권)은 TOEIC 등 YBM 시험을 고르면 YBM 로그인 창을 열고, 점수는 인증으로만 입력됩니다. K-Apply는 시험을 고르는 동안 이 창을 막고 **"직접 인증해 주세요"로 안내**하며 점수는 넣지 않습니다. YBM 연동을 쓰지 않는 기업은 점수·등급을 그대로 입력합니다.
- 이 화면의 행 삭제(−) 버튼은 **지원서 저장**을 함께 수행합니다. K-Apply는 행·블록을 삭제하지 않습니다. 기본정보 단계의 **복무 기간(개월)**, 장애·보훈 **대상**일 때의 세부 항목(등록번호·정도·유형 등)은 증빙과 일치해야 하므로 직접 입력하도록 안내합니다.

### 일부러 채우지 않는 것

| 항목 | 이유 |
| --- | --- |
| 자기소개서 · 지원 동기 등 서술형 문항 | 회사마다 질문이 달라 사용자가 직접 작성해야 합니다. |
| 지원 부문 · 직무 선택 | 어떤 포지션에 지원할지는 사용자가 결정합니다. |
| 비밀번호 · 인증번호 · 이메일 인증 | 보안상 자동화하지 않습니다. |
| 개인정보 수집 동의 · 제출 버튼 | 법적 의사 표시이므로 사용자가 직접 확인합니다. |

## 설치

> Chrome 웹 스토어 등록 전까지는 릴리스 파일로 설치합니다. Chrome 116 이상, Edge·Whale 등 Chromium 기반 브라우저에서 동작합니다.

1. [최신 릴리스](https://github.com/leestana01/K-Apply/releases/latest)에서 `k-apply-vX.Y.Z.zip`을 내려받아 압축을 풉니다.
2. 주소창에 `chrome://extensions`를 입력하고 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누르고 압축을 푼 폴더(`manifest.json`이 있는 폴더)를 선택합니다.
4. 설치가 끝나면 프로필 입력 화면이 자동으로 열립니다.

빌드 과정이 없으므로 클론한 폴더를 그대로 3번 단계에서 선택하면 됩니다.

</details>

## 사용법

1. **프로필 입력** — 툴바의 K-Apply 아이콘 → **프로필 편집**에서 정보를 입력합니다. 입력 내용은 자동 저장됩니다.
   - 학력·경력 등은 `+ 추가`로 여러 건을 등록하고 ↑↓로 순서를 바꿀 수 있습니다. 지원서에는 이 순서대로 입력됩니다.
   - **지원 경로**는 `링크드인, 채용 포털, 기타`처럼 쉼표로 여러 후보를 적으면 지원서 선택지 중 앞쪽 후보부터 고릅니다.
2. **지원서 열기** — 지원하려는 공고의 지원서 작성 화면으로 이동하면 툴바 아이콘에 배지가 표시되고, 화면 오른쪽 아래에 `K-Apply로 채우기` 버튼이 나타납니다.
3. **자동 입력** — 버튼, 팝업의 **지원서 자동 입력**, 또는 <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd>로 실행합니다.
4. **확인 후 제출** — 결과 창의 "확인 필요" 항목과 서술형 문항을 직접 채우고, 내용을 검토한 뒤 제출합니다.

> **마이다스인**은 지원서가 단계(기본정보 → 학력/경력 → 어학/자격 → 자기소개서)로 나뉘어 단계마다 저장됩니다. 각 단계 화면에서 한 번씩 실행해 주세요. 1단계의 **지원분야**를 선택해야 다음 단계로 넘어갈 수 있습니다.

## 동작 방식

```
페이지 로드 ─▶ 감지 스크립트 (모든 페이지, 읽기 전용)
                 │  호스트명 · DOM 구조 · 리소스 출처로 솔루션 판별
                 ▼
             서비스 워커 ─▶ 툴바 배지 표시 · 입력 엔진 주입
                 │
사용자 실행 ─▶ 입력 엔진 ─▶ 솔루션별 어댑터
                              ├─ 그리팅    : name 경로 매핑 + Ark UI 컨트롤
                              ├─ 나인하이어 : 항목 제목 매칭 + Ant Design 컨트롤 + 하위 입력 폼
                              ├─ 마이다스인 : name 경로 매핑 + 반복 행(data-loop) + 검색형 입력
                              └─ 마이다스인 새 화면(/v1) : 행 제목 매칭 + 버튼형 선택 · 드롭다운 · 주소 검색 창
```

각 솔루션은 React·jQuery 등 서로 다른 방식으로 입력값을 관리합니다. K-Apply는 값을 넣은 뒤 실제 사용자 입력과 같은 이벤트를 발생시키고, 검색형 입력(학교·회사·자격증 등)은 제안 목록에서 일치 항목이나 "직접 입력"을 골라 값을 확정합니다. 자세한 구조는 [docs/architecture.md](docs/architecture.md)를 참고하세요.

## 개인정보와 권한

- **모든 데이터는 사용자의 브라우저(`chrome.storage.local`)에만 저장됩니다.** 외부 서버로 전송하지 않으며, 분석·광고 코드가 없습니다.
- 첨부 파일은 사용자가 업로드를 실행한 지원서 페이지에만 전달됩니다.
- 프로필은 **백업 · 초기화**에서 JSON으로 내보내거나 모두 삭제할 수 있습니다.

| 권한 | 사용 목적 |
| --- | --- |
| `storage`, `unlimitedStorage` | 프로필과 첨부 파일(최대 20MB × 3)을 브라우저에 저장 |
| `scripting` | 감지된 지원서 페이지에 입력 엔진과 파일 첨부·업로드 검증 브리지를 주입 |
| 모든 사이트 접근 (`http://*/*`, `https://*/*`) | 기업 전용 도메인으로 운영되는 채용 사이트까지 자동 감지하기 위해 필요합니다. 감지 스크립트는 페이지 구조만 확인하며 입력값을 읽거나 전송하지 않습니다. |

자세한 내용은 [개인정보 처리 방침](PRIVACY.md)을 확인하세요.

## 자주 묻는 질문

<details>
<summary>배지가 표시되는데 버튼이 보이지 않아요.</summary>

배지는 채용 사이트임을, 버튼은 지원서 작성 화면이 열렸음을 뜻합니다. 공고 상세 화면에서 **지원하기**를 눌러 지원서 화면으로 이동해 주세요. 버튼을 숨겼다면 설정에서 다시 켤 수 있고, 팝업이나 단축키로도 실행할 수 있습니다.
</details>

<details>
<summary>학교명이 "확인 필요" 또는 "실패"로 표시돼요.</summary>

학교는 코드 목록에서 골라야 정확히 전달됩니다. "목록에 없어 직접 입력"이면 프로필의 학교명을 공식 명칭(예: `서울대학교`)으로 고쳐 주세요. "여러 항목이 있어 고르지 않았습니다"라면 프로필의 **캠퍼스**(예: `관악`)를 입력한 뒤 다시 실행하거나 화면에서 직접 선택해 주세요.
</details>

<details>
<summary>첨부 파일이 "실패"로 표시돼요.</summary>

사유에 따라 다음을 확인해 주세요.

- **등록 당시와 다릅니다 / 내용이 없습니다** — 저장된 파일이 손상됐습니다. 프로필 편집 화면에서 파일을 다시 등록해 주세요.
- **형식을 요구합니다** — 업로드 칸이 요구하는 형식(예: PDF)으로 변환해 다시 등록해 주세요.
- **서버로 전송되는 것을 확인하지 못했습니다** — 네트워크 상태나 사이트 변경으로 업로드를 확인하지 못했습니다. 화면의 첨부 상태를 직접 확인해 주세요.
</details>

<details>
<summary>이미 입력한 내용이 바뀌나요?</summary>

기본값으로는 비어 있는 칸만 채웁니다. 설정의 **이미 값이 있는 칸도 덮어쓰기**를 켠 경우에만 기존 값을 바꿉니다. 반복 항목은 같은 순서의 항목이 이미 채워져 있으면 건너뜁니다. 이미 첨부된 파일은 설정과 관계없이 항상 유지합니다.
</details>

<details>
<summary>단축키를 바꾸고 싶어요.</summary>

`chrome://extensions/shortcuts`에서 **현재 지원서 자동 입력** 단축키를 변경할 수 있습니다.
</details>

## 개발

런타임 의존성이 없는 순수 JavaScript(Manifest V3) 프로젝트입니다. Node.js 20 이상이 필요하며, 개발 도구로 ESLint만 사용합니다.

```bash
npm ci            # 개발 의존성(ESLint) 설치
npm run lint      # ESLint (미정의 식별자 등)
npm test          # 단위 테스트 (node:test)
npm run check     # manifest·참조 파일·문법 점검
npm run verify    # lint + test + check
npm run package   # dist/k-apply-vX.Y.Z.zip 생성
```

```
src/
├── background/service-worker.js   # 배지, 엔진 주입, 단축키
├── content/
│   ├── detector.js                # 모든 페이지에서 실행되는 감지 스크립트
│   ├── dom.js · controls.js       # DOM 이벤트 · UI 컴포넌트별 입력기
│   ├── engine.js                  # 입력 세션, 결과 리포트, 파일 브리지
│   ├── runner.js                  # 메시지 처리, 플로팅 버튼, 결과 토스트
│   └── adapters/                  # greeting.js · ninehire.js · midas.js
├── main/file-bridge.js            # 페이지 컨텍스트 파일 첨부 브리지
├── shared/                        # 스키마, 저장소, 감지 규칙, 라벨 매처, 텍스트 유틸
├── popup/ · options/ · ui/        # 팝업, 프로필 편집 화면, 공통 스타일
tests/                             # 순수 로직 단위 테스트
```

새 채용 솔루션을 추가하려면 [docs/adding-a-platform.md](docs/adding-a-platform.md)를 참고하세요.

## 면책

K-Apply는 각 채용 솔루션과 제휴하지 않은 비공식 오픈소스 프로젝트입니다. 그리팅, 나인하이어, 마이다스인 및 관련 상표는 각 소유자의 자산입니다. 솔루션의 화면 구조가 바뀌면 일부 항목이 입력되지 않을 수 있으며, 제출 전 입력 내용을 반드시 확인해 주세요.
