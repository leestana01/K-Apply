# 아키텍처

K-Apply는 빌드 도구와 런타임 의존성이 없는 Manifest V3 확장프로그램입니다. 모든 스크립트는 `globalThis.KApply` 네임스페이스에 모듈을 등록하는 IIFE 형태로, 콘텐츠 스크립트·확장 페이지·서비스 워커·Node 테스트에서 같은 파일을 그대로 불러옵니다.

## 실행 흐름

```
┌──────────────────────── 모든 http(s) 페이지 ─────────────────────────┐
│ content_scripts: shared/platforms.js + content/detector.js           │
│   · 호스트명 / DOM 시그니처 / 리소스 출처로 솔루션 판별                    │
│   · SPA 화면 전환은 MutationObserver로 재평가 (700ms 디바운스)            │
│   · 결과만 서비스 워커로 보고: { platform, formReady }                   │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
┌──────────────────── background/service-worker.js ─────────────────────┐
│ · 탭별 배지(G/9/M)와 제목 갱신                                          │
│ · 입력 엔진 주입 (chrome.scripting.executeScript, ISOLATED world)        │
│ · 팝업·단축키의 실행 요청을 탭으로 전달                                   │
│ · 파일 브리지 주입 (MAIN world, 요청 시에만)                              │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
┌──────────────────────── 입력 엔진 (ISOLATED) ─────────────────────────┐
│ runner.js   메시지 처리 · 플로팅 버튼 · 결과 토스트 (Shadow DOM)          │
│ engine.js   Session: 프로필 조회 · 값 변환 · 결과 기록 · 파일 준비          │
│ adapters/*  솔루션별 화면 구조 해석 → Session.apply()로만 값 변경           │
│ controls.js 네이티브 / Ark UI / Ant Design / 마이다스인 컨트롤 입력기       │
│ dom.js      React·jQuery가 인식하는 이벤트 시퀀스                          │
└──────────────────────────────────────────────────────────────────────┘
```

자동 입력은 **항상 사용자 동작(버튼·팝업·단축키)으로만 시작**합니다. 감지 스크립트는 입력값을 읽지 않고, 엔진은 제출·동의 버튼을 누르지 않습니다.

## 데이터 모델

`src/shared/schema.js`가 단일 기준입니다. 옵션 화면은 이 정의로 폼을 그리고, 저장소는 이 정의로 데이터를 정제(`sanitizeProfile`)하며, 어댑터는 섹션·필드 키로 값을 읽습니다.

| 종류 | 섹션 |
| --- | --- |
| 단일(`single`) | `basic`, `links`, `application`, `military` |
| 목록(`list`) | `educations`, `careers`, `projects`, `activities`, `trainings`, `languages`, `certificates`, `awards` |

날짜는 `YYYY-MM-DD`(일자) 또는 `YYYY-MM`(연월)로 저장하고, 입력 시점에 대상 컨트롤의 포맷으로 변환합니다. 선택형 값은 `shared/text.js`의 동의어 사전(`SYNONYMS`)으로 화면 선택지와 맞춥니다.

## 값을 확정하는 방법

프레임워크마다 "값이 바뀌었다"를 인식하는 방식이 달라, 단순히 `input.value`를 바꾸는 것으로는 부족합니다.

| 대상 | 방법 |
| --- | --- |
| React 제어 입력 | 프로토타입 setter로 값을 넣고 `input` 이벤트 발생 (값 추적기 우회) |
| jQuery 핸들러 | `input` · `change` · `keyup` · `blur`를 순서대로 발생 |
| Ark UI Select | 트리거 클릭 → 목록 항목 클릭 |
| Ark UI DatePicker | 팝오버 안의 입력창에 `YYYY-MM-DD` 입력 후 Enter |
| Ark UI Combobox | `focusin` → `InputEvent` → 비동기 제안 목록에서 일치 항목 또는 "직접 입력하기"(`[[new]]`) 선택 → `focusout` |
| Ant Design Dropdown | 이전 메뉴가 닫힐 때까지 기다린 뒤 새로 열린 메뉴에서 선택 |
| Ant Design DatePicker | 설정 포맷을 읽을 수 없으므로 흔한 포맷을 차례로 입력하고, 포커스를 뺀 뒤 값이 남는지로 확정 여부 판단 |
| 마이다스인 검색 입력 | 키워드 입력 → Enter(`keypress`) → 결과 버튼 또는 "직접 등록하기" 클릭 |

브라우저 창이 포커스를 잃은 상태에서는 `element.focus()`가 포커스 이벤트를 만들지 않으므로, 포커스가 필요한 컨트롤에는 `focus`/`focusin` 이벤트를 직접 보냅니다.

## 코드 목록 선택 규칙

학교·전공·자격증·어학시험·회사명은 솔루션마다 코드가 붙은 검색 목록에서 고릅니다. 판단은 DOM과 무관한 `text.matchListed()`가 담당하고, 입력기(`controls.js`)는 결과만 적용합니다.

1. 정규화한 이름(+캠퍼스)이 정확히 같은 항목이 있으면 선택
2. `이름 (캠퍼스)` 형태 항목이 하나뿐이고 캠퍼스를 지정하지 않았으면 선택하되 "확인 필요"
3. 캠퍼스별 항목이 여럿이거나 지정한 캠퍼스가 없으면 **선택하지 않고 실패**
4. 목록에 없으면 "직접 입력하기"를 선택하고, 학교·전공처럼 코드가 중요한 항목은 "확인 필요"
5. 부분 일치(예: `서울대학교` ↔ `남서울대학교`)로는 고르지 않음

솔루션별 목록 여는 방식은 다릅니다.

| 솔루션 | 방식 |
| --- | --- |
| 그리팅 | Ark Combobox: `focusin` + `InputEvent` 후 비동기 목록이 안정될 때까지 대기 |
| 나인하이어 | 입력값을 넣은 뒤 입력 영역을 클릭해 드롭다운을 열어야 코드 검색 API가 호출됨 |
| 마이다스인 | 검색창 Enter(`keypress`) → 결과 버튼(`data-code`) 또는 "직접 등록하기" |

## 주소 입력

주소는 값을 직접 써 넣지 않고 각 사이트의 주소 검색을 거칩니다. 사이트가 저장하는 값(장소 ID·좌표 등)이 검색 결과에서만 만들어지기 때문입니다.

| 솔루션 | 구현 |
| --- | --- |
| 그리팅 | "주소 찾기" → 모달 검색창(`type=search`)에 도로명 주소 입력 → Enter(Google Places) → 결과 중 `주소…우편번호NNNNN` 텍스트가 프로필과 모두 같은 항목 클릭 → 읽기 전용 칸의 값 검증 |
| 나인하이어 | 브리지 `arm-postcode`: 다음 1회 `new daum.Postcode(options)`를 가로채 위젯 대신 `options.oncomplete({ zonecode, roadAddress, jibunAddress, … })` 호출 → 화면 반영 확인 → 상세 주소 입력 |
| 마이다스인 | "우편번호" → postcodify 검색창에 도로명 주소 입력 → 결과 중 `.code5`·`.address_info`가 모두 같은 항목 선택. 검색 창을 찾지 못하면 값을 직접 입력하고 "확인 필요" |

옵션 화면의 주소 검색은 postcodify 공개 API(`api.poesis.kr`, 예비 `api.poesis.co.kr`)를 호출합니다. 원격 코드는 불러오지 않고 JSON만 받습니다.

## 파일 첨부와 업로드 검증

```
옵션 화면 등록 ── 크기·SHA-256 기록 → 저장 직후 재검증 (빈 파일 거부)
        │
자동 입력 ─── ① storage.loadFile(): 크기·SHA-256 재검증, 불일치·누락 시 실패
              ② 업로드 칸의 요구 형식(accept, "PDF 형식으로…") 확인
              ③ 브리지에 watch 등록 (크기·해시)
              ④ 첨부 ─ input[type=file]: DataTransfer → 들어간 파일 해시 확인 → change
                     └ 임시 input(나인하이어): 브리지가 다음 파일 선택 1회를 가로채 주입
              ⑤ 브리지가 fetch/XHR 본문(Blob·FormData) 중 크기·해시가 같은 요청의 응답을 관찰
              ⑥ 2xx일 때만 성공 → 화면 첨부 상태 확인(confirm) · 거부 표시 즉시 실패(rejected)
```

- 그리팅은 파일 선택 즉시 사전 서명 URL로 S3에 `PUT`, 나인하이어는 S3에 `POST`(FormData)합니다. 두 경우 모두 요청 본문에서 원본과 같은 바이트를 확인합니다.
- 브리지(`src/main/file-bridge.js`)는 MAIN world에서 실행되며, 감시 중인 파일이 없을 때는 요청을 들여다보지 않습니다. 요청을 변경하거나 지연시키지 않습니다.
- 이미 첨부된 파일은 삭제에 확인 창이 필요한 파괴적 동작이므로 덮어쓰기 설정과 관계없이 유지합니다.
- 마이다스인 첨부 칸은 형식 오류 시 `alert()`로 페이지를 멈추는 검증기를 쓰므로 자동 첨부하지 않고 안내만 합니다.

## 결과 상태

`engine.js`의 `Session.apply()`는 입력기의 반환값(`boolean` 또는 `{ ok, review, reason, detail }`)을 다음 상태로 기록합니다.

| 상태 | 조건 |
| --- | --- |
| `filled` | 입력과 반영 확인 완료 |
| `review` | 입력했지만 사용자 검토 필요 |
| `failed` | 입력 실패 또는 검증 불통과 (사유 포함) |
| `manual` | 사용자가 직접 해야 하는 항목 |
| `skipped` | 이미 값이 있음 |

## 솔루션별 특징

### 그리팅

- 입력 요소의 `name`이 폼 경로입니다. 예: `basicInformation.name`, `workHistory.workExperiences.0.companyName`.
- 반복 항목은 인덱스로 구분되며, 섹션 안의 `항목 추가` 버튼으로 행을 늘립니다.
- 기업 커스텀 도메인은 `*.greetinghr.com` 리소스 참조로 감지합니다.

### 나인하이어

- `name`이 없어 항목 블록(`ApplicationFormInput__Layout`)의 제목(`EditableLabel__Input`)으로 의미를 판별합니다.
- 학력·경력 등 일반 항목은 하위 입력 폼을 채우고 `입력사항 저장`을 눌러 한 건씩 추가합니다. 저장된 목록에 같은 이름이 있으면 건너뜁니다.

### 마이다스인

- 단계별로 저장되는 다단계 지원서입니다. 각 단계 화면에 있는 항목만 채웁니다.
- 반복 항목은 `div[data-loop="<이름>"]` 행과 `name="<이름>[i].<필드>"`를 쓰며, 행 안의 `[data-button="add"]`(대학은 `[data-button="addCollege"]`)로 행을 추가합니다.
- 대표 항목을 고르기 전에는 연동 필드가 `disabled`이므로, 정해진 순서로 입력하며 활성화를 기다립니다.
- 날짜 포맷은 `data-dates="<그룹>:<YMD|YM|END>"`에서 결정합니다.

#### 마이다스인 새 화면 (`/v1/applicant/resume-form`)

기존 화면과 호스트는 같지만 React + react-hook-form으로 새로 만든 화면입니다. `midas.js`가 경로·`name` 형식(`basicInfoGroupAnswers.*`)으로 새 화면을 알아보고 `midas-v1.js`에 위임합니다.

| 컴포넌트 | 구조 | K-Apply의 동작 |
| --- | --- | --- |
| 텍스트 | `name="basicInfoGroupAnswers.name"` 같은 경로형 `name` | `name`으로 매핑 |
| 날짜 | `name` 없이 `placeholder`(`YYYY.MM.DD`, `입대일`, `제대일`)만 있는 텍스트 칸 | 행 제목·placeholder로 찾아 `YYYY.MM.DD`로 입력 후 값 확인 |
| 버튼형 선택 | `li > button`, 선택된 버튼은 흰 배경 인라인 스타일. 장애·보훈·병역은 처음부터 `비대상`이 선택됨 | 선택 스타일로 결과 확인. 기본 선택 `비대상`은 입력 전으로 취급 |
| 드롭다운 | 단독 버튼 → 검색창 + `li > button[value]` 목록 | 전체 목록에서 동의어로 고른 뒤 버튼 문구로 확인 |
| 주소 | [주소입력] → `[role=dialog]` 검색 창 → 결과(`도로명 … 지번 …`) → [확인] | 도로명(+지번)이 같은 결과가 하나일 때만 선택, 채워진 우편번호·주소를 프로필과 대조 |
| URL | [추가하기]로 `socialMediaAnswerList.N.address` 행 추가 | 이미 있는 URL은 건너뜀 |
| 검색형 입력 (학교·전공·회사명) | 입력하면 결과 목록(`ul > li > button`, 값 속성 없음)이 열리고, 같은 이름이 없으면 `'검색어'등록하기` 항목이 붙음. 선택하면 입력칸이 이름 텍스트로 바뀜 | 결과가 안정될 때까지 기다린 뒤 이름이 정확히 같은 항목만 선택, 없으면 직접 등록(학교·전공은 "확인 필요") |
| 검색형 반복 행 (공인외국어시험·자격증) | [추가하기]로 행 추가 → 검색 → 선택하면 검색 칸이 든 영역이 새 요소(이름 칩 + 세부 입력칸)로 교체됨. 응시일·취득일은 `YYYY.MM` 마스크 | 선택 결과는 [추가하기]를 포함하는 고정 영역에서 확인하고, 선택 후 새로 생긴 입력칸으로 행을 찾음 |
| YBM 성적 연동 | 기업 설정 `useYBMYn`이 켜져 있고 시험의 `setupCode`가 `EXAM_CODE`면, 선택 즉시 `window.open` + `form.submit`으로 YBM 로그인 창을 열고 점수 칸을 비활성화 | 선택하는 동안 페이지 브리지가 새 창 열기를 막고(`withPopupGuard`), 막았다면 점수를 넣지 않고 직접 인증을 안내 |
| 항목 블록 (학력·경력) | [+ 고등학교] 등으로 추가, 머리글 `- 고등학교`, 머리글의 세 번째 버튼이 삭제 | 같은 이름이 이미 입력된 블록은 건너뛰고, 빈 블록을 먼저 사용 |

항목 이름은 입력 칸이 아니라 같은 행 앞쪽의 텍스트 요소에 있으므로, 조상을 거슬러 올라가며 컨트롤이 없는 앞쪽 형제의 짧은 텍스트를 행 제목으로 씁니다. 항목 블록 안에서는 선택한 학교명이나 `/` 같은 텍스트가 컨트롤 앞에 끼므로, 반대로 제목 텍스트에서 출발해 컨트롤을 포함하는 첫 조상을 행으로 봅니다. 단계 이동 버튼과 행 삭제(−) 버튼은 저장을 동반하므로 누르지 않습니다.

## 테스트 전략

- `npm run lint`: ESLint로 미정의 식별자·미사용 변수 등 런타임에만 드러나는 오류를 막습니다.
- `tests/`는 DOM에 의존하지 않는 순수 로직(정규화, 선택지·코드 목록 매칭, 파일 형식 판별, 날짜·전화번호 변환, 스키마 정제, 파일 무결성, 라벨 매칭, 감지 규칙)을 `node:test`로 검증합니다.
- 어댑터는 실제 채용 사이트 화면 구조에 의존하므로, 변경 시 공개 공고의 지원서 화면에서 **제출하지 않고** 동작을 확인한 결과를 PR에 기록합니다.
